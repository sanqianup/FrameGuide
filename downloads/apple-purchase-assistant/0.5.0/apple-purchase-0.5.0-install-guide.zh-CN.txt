Apple 购买工作流 0.5.0 · 候选实测版（浏览器安装验收待完成）

一、先看适用范围
本版增加可配置的购买执行器：选择规格 → 加入购物袋 → 填写或确认地址 → 复核订单 → 仅提交明确不扣款的未付款订单 → 停在付款前。它不是已经验证适配 Apple 全部结账页面的成品预设。已观察到18Pro加购、购物袋和安全结账登录入口；地址、复核与提交页面结构尚未拿到，必须先由你校准精确目标及证据映射；缺失、歧义或未知页面会停止。不能保证抢购成功。

原有本地模拟、官网只读和颜色/容量配置模式保留。旧配置模式仍仅负责非交易规格步骤。购买工作流使用同一扩展里的统一设置页：一份步骤计划、一次开始/停止、一个任务状态，不需要先手动串接原规格任务。可设启动时间，留空立即开始。

二、安装
1. 完整解压 ZIP，保留文件夹。
2. Chrome 打开 chrome://extensions，Edge 打开 edge://extensions。
3. 自行开启开发者模式，选择“加载已解压的扩展程序”。
4. 选择本包 extension 文件夹，该层直接有 manifest.json。
5. 固定扩展图标。打开弹窗，再进入“购买工作流”设置页。
不需要 Node、npm、服务器或调试端口。无需向开发者提供密码或任何凭据。请使用你自己的浏览器，自行登录 Apple、处理验证码及双因素验证。

三、重要边界
- 必须由你逐次确认 Apple 中国站及精确安全结账域、精确商品规格、数量与最高含税费和运费总价。历史标价不是授权，商品价不是完整订单总额。
- 插件不会替你输入支付卡号、密码或验证码，不会自动支付。不使用云端登录，不把地址发送给模型或外部服务。
- 按钮叫“提交订单”不证明其不扣款。只有明确、独立、可见的未付款/不立即扣款证据，配合正确订单摘要和授权上限，才允许提交。页面涉及立即支付、扣款授权或含义不明时停下，由你自行点击。
- 未确认的提交不会重试，停止或重启不能当作重新提交的理由。先人工核实 Apple 订单记录。
- 只在你配置的精确页面之间连续推进，允许域仅 www.apple.com.cn 和已验证的 secure6.www.apple.com.cn。跳到未配置路径、其他域名、登录/验证码/排队页会停下。
- 默认地址需要本地核对确认；新增地址由你在扩展本地填写，默认只保留本次会话，可清空。只有你明确勾选本机保存同意并点击保存按钮时，才写入此浏览器的独立本地地址预设；它不加密，不会随安装包分发或跨设备同步，也不进入普通设置、诊断日志或导出。可用“清除本机地址资料”删除，并停止正在使用该资料的流程。

四、当前已知页面证据
现有 Duo 配置预设仅依据已观察的中国站 dimensionColor / dimensionCapacity 单选组及商品摘要控件。mk2n4ch/a 曾观察到 256GB 夜空色商品价15999，继续仍禁用、暂未发售；你指定的 mk2u4ch/a 公开文本为1TB夜空色、21499，但未验证其动态DOM状态。这些都不是购物袋或结账页面证据。
购买工作流不限定只能Duo，允许你明确配置其他中国站商品和路径；18Pro预登录流程有实际观察证据，地址和最终提交仍没有可用的官网预设。

新增实页证据：18Pro256GB黑色（SKU MJT74CH/A）1台，添加到购物袋后进入附件页，点击“查看购物袋”。购物袋可见数量1、小计9999、运费免费、总计9999，无配件/换购/AppleCare；结账进入 secure6.www.apple.com.cn/shop/signIn。会话查询参数不保存、不硬编码。登录仍由用户自行操作；这不是最终订单已提交的证据。

送货步骤实际路径为 secure6.www.apple.com.cn/shop/checkout，观察到“为我送货/我要取货”、省市区选择和“继续填写送货地址”。区县未选会必填报错。后来官方进入“来得早，来得好。北京时间晚8点接受预购”的维护/预购暂停页。插件对此停止，不刷新、不把宣传时间当任务倒计时。完整地址字段及最终付款/提交结构仍未观察。

五、统一设置与地址识别
使用可视化步骤卡编辑规格、购物袋、地址、订单复核和未付款提交；高级JSON仅供导入，不是必需入口。页面已核验的名称可预填，未知证据留空并阻止执行。
新地址优先用标准 autocomplete 及控件名称识别，唯一匹配才填。支持姓名或姓/名、电话、邮编、街道、省市区原生表单；触发 input/change 后重新定位，省市区级联等待选项出现。非标准地区弹层、缺少选项、未知必填项或填写后不匹配会暂停，不能随意给未知字段填值。
支付卡、密码、OTP、身份验证等不属于自动填写范围。

六、执行与停止
点击开始后立即监听 DOM，到你设定的启动时间才执行动作，使用变化事件和语义重定位，不等页面完全加载，不自动刷新网络。每步点击前重新核实当前目标和证据，保存单次许可，点击后等待独立状态确认。
关闭普通弹窗不应导致后台任务丢失。工作流的停止按钮会取消后续动作，但已经发生的点击或地址填写无法撤销。原生控件变化不等于网页应用完成；没有真实页面响应就停止，不盲目重复。

七、测试与反馈
随包提供测试源码、实际测试输出和实测清单。Node 模拟DOM/Chrome API 回归并不等于真实 Chrome/Edge 端到端通过。本方尚未实际加载0.5扩展验收，也没有登录、填真实地址、加购、下单或付款。
如实测失败，提供扩展版本、浏览器版本、脱敏后的目标页面结构、状态和错误文字。不要提供密码、Cookie、支付信息或完整地址。未知DOM需校准后再测试，不能靠反复开始跳过保护。

八、先运行包内模拟商城
安装后从弹窗或购买流程页进入“完整模拟商城”。所有商品、地址、订单都是虚构数据，不需要Apple登录；用同一后台和执行器运行，页面会记录实际浏览器耗时及重复次数。默认未运行时没有任何性能结果。
普通HTTP页面仅演示网页DOM交互，并不验证扩展。开发端安装受工具策略阻塞，HTTP跨环境访问也被拒绝，因此本包交给你手动安装验收；不能说开发端已完成实际浏览器测试。
如果只想在本机看纯HTTP演示，可在extension目录运行 python -m http.server 8765 --bind 127.0.0.1，再打开 http://127.0.0.1:8765/workflow-fixture.html。Windows若使用py启动器，把python换成py。此操作不是加载扩展。

最终真实订单提交屏障在发出动作前写入；本版不提供自动解除或一键重试。已确认或未知结果后请到官网核对，避免重复购买。假商城的“重新演练”只清理隔离测试记录，不解除真实订单屏障。
